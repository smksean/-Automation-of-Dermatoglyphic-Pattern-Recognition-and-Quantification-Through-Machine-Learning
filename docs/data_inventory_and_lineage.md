# Data Inventory and Lineage

This project should be reproducible from the Git repository plus separately
authorized access to the NIST source data and private project secrets. The
repository must not contain the full biometric datasets, private review images,
annotation exports, Streamlit secrets, Supabase service keys, or trained model
payloads.

Use this file as the map when moving the project to another computer.

## Storage Rule

Keep these files in Git:

- source code, notebooks with outputs cleared, tests, aggregate results, figures
  that do not expose subject-linked biometric records, documentation, and model
  checksum manifests

Keep these outside Git:

- raw SD 302 image and EBTS folders
- generated image arrays and review packages under `data/`
- local annotation exports
- `.streamlit/secrets.toml`, `.env`, Supabase keys, and access codes
- checkpoint files such as `*.pt`, `*.pth`, `*.ckpt`, and serialized baselines
  such as `*.joblib`

## Label Source

The broad labels are not model-generated labels. They are derived from
examiner-supplied ANSI/NIST pattern entries in EBTS field `9.307`, then linked
to the corresponding rolled fingerprint image files.

Current broad mapping:

| EBTS pattern code | Project broad class |
|---|---|
| `AU`, `AU+PA`, `AU+TA` | `arch` |
| `LS` | `left_slant_loop` |
| `RS` | `right_slant_loop` |
| `WU`, `WU+PW`, `WU+CP`, `WU+DL`, `WU+AW` | `whorl` |

Subtype detail is treated more cautiously. Codes such as `AU+PA`, `AU+TA`,
`WU+PW`, `WU+CP`, `WU+DL`, and `WU+AW` provide subtype evidence when present.
Generic `AU` and `WU` identify the main type but do not identify the exact
subtype. Multiple `9.307` entries may be legitimate alternative classifications,
so they must not be collapsed into a single definitive label without review.

## What To Do Next

Do not push the raw data or review packages to GitHub. For a new laptop:

1. Clone this repository.
2. Recreate the same ignored raw-data folder names from the approved NIST
   downloads or a secure private transfer.
3. Restore or regenerate `data/processed/` from the notebooks and scripts.
4. Keep `.streamlit/secrets.toml` and Supabase service keys private.
5. Treat existing NIST `9.307` links as source annotations for broad labels,
   not as completed expert subtype labels.
6. Continue subtype review through `annotation_app/` and the private Supabase
   backend, or through the local package if cloud storage has not been approved.
7. Use the restored `subtype_subject_linkage.csv` for grouped subtype validation.
   Commit only aggregate statistics or non-sensitive code/results unless
   data-governance approval says otherwise.

The important conceptual split is this: broad classification can already use
the linked NIST codes; subtype classification should wait for the expert-review
outputs because generic `AU` and `WU` do not carry exact subtype labels.
